01

Как устроено окно

Чем OVER отличается от GROUP BY и из чего он состоит.

Что спросят
  • Чем оконная функция отличается от агрегата с GROUP BY?
  • Что делают PARTITION BY, ORDER BY и рамка окна?
  • Почему оконная функция не выполняется в WHERE?
Вопросы и ответы
Чем окно отличается от GROUP BY?
GROUP BY схлопывает строки: на группу остаётся одна строка. Окно считает агрегат, но сохраняет каждую исходную строку и добавляет к ней результат. Поэтому в одном запросе можно сразу видеть и детальную строку, и её агрегат по группе.
Из чего состоит OVER()?
Из трёх частей: PARTITION BY — на какие группы делим строки; ORDER BY — как упорядочиваем внутри группы (нужен для ранжирования и рамок); рамка (например ROWS BETWEEN ...) — какие строки окна участвуют в вычислении.
Почему нельзя написать окно в WHERE?
Логический порядок выполнения: WHERE выполняется до оконных функций. Отфильтровать результат окна можно только во внешнем запросе или в QUALIFY (если он поддерживается — например, в Snowflake, DuckDB, BigQuery).
  • PARTITION BY задаёт группы, внутри которых считаем; без него окно — вся выборка.
  • ORDER BY в окне не сортирует финальный результат — он задаёт порядок внутри окна.
  • Без ORDER BY рамка по умолчанию — все строки партиции; с ORDER BY — от начала до текущей строки.
Вывод составителяДержите в голове одну мысль: окно не меняет число строк. Если в задаче сказано «и при этом сохранить детализацию» — это почти всегда сигнал к оконной функции.
02

Ранжирование

ROW_NUMBER, RANK, DENSE_RANK — и когда какой брать.

Что спросят
  • Разница между ROW_NUMBER, RANK и DENSE_RANK?
  • Как достать топ-1 (или топ-N) на каждую группу?
  • Как удалить дубликаты, оставив самую свежую запись?
Вопросы и ответы
ROW_NUMBER vs RANK vs DENSE_RANK?
При равных значениях ROW_NUMBER выдаёт уникальные номера подряд (1, 2, 3, 4), RANK даёт одинаковым одинаковый номер и пропускает следующие (1, 1, 3, 4), а DENSE_RANK не пропускает (1, 1, 2, 3).
Как взять топ-1 на группу?
Нумеруем строки внутри группы и фильтруем по номеру во внешнем запросе. Именно снаружи — потому что фильтровать окно в WHERE нельзя.
Пример
-- последний заказ каждого клиента
SELECT client_id, order_id, amount, created_at
FROM (
  SELECT
    o.*,
    ROW_NUMBER() OVER (
      PARTITION BY client_id
      ORDER BY created_at DESC
    ) AS rn
  FROM orders o
) t
WHERE rn = 1;
Частые ошибки
  • Пытаются отфильтровать rn = 1 в том же запросе — так нельзя, нужен подзапрос или CTE.
  • Берут RANK там, где нужна ровно одна строка на группу — при равенстве ключей получите несколько.
  • Забывают детерминировать сортировку: при одинаковом created_at результат «плавает».
Вывод составителяОдна фраза для интервью: «row_number — всегда уникален, rank — соревновательный, dense_rank — без пропусков». Этого достаточно, чтобы снять вопрос.
03

Смещение строк

LAG, LEAD и FIRST_VALUE — сравнение с соседними строками.

Что спросят
  • Как посчитать изменение метрики к прошлому периоду?
  • Как найти первый заказ клиента?
Вопросы и ответы
Что делают LAG и LEAD?
LAG возвращает значение из предыдущей строки окна, LEAD — из следующей. Второй аргумент — на сколько строк назад/вперёд, третий — значение по умолчанию, если строки нет.
Пример
-- прирост выручки к предыдущему месяцу
SELECT
  month,
  revenue,
  revenue - LAG(revenue, 1, 0) OVER (ORDER BY month) AS delta
FROM monthly_revenue;
Вывод составителяЕсли задача звучит как «сравнить с предыдущим / следующим», это LAG/LEAD. Если «первое или последнее в группе» — FIRST_VALUE/LAST_VALUE, причём для LAST_VALUE нужно явно задать рамку до конца партиции.
04

Агрегаты и рамки

Нарастающие итоги, скользящее окно и роль ROWS BETWEEN.

Что спросят
  • Как посчитать нарастающий итог (running total)?
  • Что такое рамка окна и как задать скользящий период?
  • Чем ROWS отличается от RANGE?
Вопросы и ответы
Как сделать running total?
Использовать агрегат как оконную функцию с ORDER BY: рамка по умолчанию (от начала партиции до текущей строки) как раз и даёт нарастающий итог.
ROWS или RANGE?
ROWS считает по физическим строкам, RANGE — по значениям ORDER BY и включает все строки с одинаковым значением. Если в датах или метрике есть дубли, разница становится заметной.
Пример
-- нарастающий итог и скользящее среднее за 3 дня
SELECT
  day,
  amount,
  SUM(amount) OVER (ORDER BY day) AS running_total,
  AVG(amount) OVER (
    ORDER BY day
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
  ) AS avg_3d
FROM daily_sales;
Вывод составителяРамка — то, чем опытный кандидат отличается от начинающего: первый сразу уточняет ROWS/RANGE и границы, второй берёт поведение по умолчанию и получает неверный итог на дублях.
05

Задачи с решениями

Три типовые задачи, которые любят давать на SQL-секции.

Задача 1. Вторая по величине зарплата
SELECT DISTINCT salary
FROM (
  SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rk
  FROM employees
) t
WHERE rk = 2;

Здесь нужен именно DENSE_RANK: при одинаковых зарплатах «вторая по величине» не должна пропадать.

Задача 2. Дедупликация с выбором свежей записи
SELECT *
FROM (
  SELECT *, ROW_NUMBER() OVER (
    PARTITION BY user_id
    ORDER BY updated_at DESC, id DESC
  ) AS rn
  FROM users_raw
) t
WHERE rn = 1;
Задача 3. Непрерывные дни активности (gaps and islands)
WITH numbered AS (
  SELECT
    user_id,
    activity_date,
    activity_date - INTERVAL '1 day' * ROW_NUMBER() OVER (
      PARTITION BY user_id ORDER BY activity_date
    ) AS grp
  FROM activity
)
SELECT user_id, MIN(activity_date) AS start_date, MAX(activity_date) AS end_date
FROM numbered
GROUP BY user_id, grp;
Вывод составителяНа интервью важно проговаривать план: «сначала нумерую внутри группы, потом фильтрую снаружи». Молчаливое написание кода — самая частая причина провала SQL-секции, даже когда запрос верный.
Итог

Общий вывод составителя

Оконные функции — это про контекст строки. Как только в задаче появляется «внутри группы», «по каждому клиенту», «сравнить с предыдущим» или «не потерять детализацию», речь почти наверняка про OVER.

Запомните три опоры: разбиение (PARTITION BY), порядок (ORDER BY) и рамку (ROWS/RANGE BETWEEN). И держите в голове порядок выполнения: окно считается после WHERE и GROUP BY, поэтому фильтровать его нужно снаружи или в QUALIFY.

Отдельно потренируйтесь объяснять вслух разницу ROW_NUMBER / RANK / DENSE_RANK и показывать на доске, почему решение требует подзапроса. Именно этот «рассказ вслух» и оценивает интервьюер.
