01

Оценка сложности

O(1), O(n), O(log n), O(n log n) — и зачем это на интервью.

Что спросят
  • Что означает запись O(n) и O(1)?
  • Почему поиск в множестве быстрый, а в списке — медленный?
  • Как оценить сложность собственного решения?
Вопросы и ответы
Что такое большая O?
Это оценка того, как время работы растёт с размером входных данных, с точностью до константы. O(1) — время не зависит от n, O(n) — растёт линейно, O(log n) — логарифмически, O(n log n) — типична для сортировки, O(n²) — квадратично (вложенные циклы).
Почему поиск в dict/set — O(1)?
Они основаны на хеш-таблице: по значению считается хеш, который указывает на «ячейку» почти напрямую. В списке же элемент ищут перебором — O(n). Отсюда классический приём: превратить список в множество, чтобы заменить поиск на константный.
Почему O(n²) — это плохо?
При n в миллион квадрат — это 10¹² операций, что недопустимо медленно. Вложенный цикл по двум большим коллекциям почти всегда имеет линейную альтернативу через словарь или множеств: это и есть цель оптимизации.
Пример
items = list(range(1000000))

# O(n): перебор списка
def has_linear(items, target):
    return target in items

# O(1) в среднем: проверка по множеству
def has_fast(items, target):
    unique = set(items)
    return target in unique
Частые ошибки
  • Оценивают константы, а не порядок роста — интервьюеру важна асимптотика.
  • Забывают про стоимость создания множества/словаря: O(n) один раз окупает себя при частых поисках.
  • Считают, что x in list — быстрая операция, и строят на ней решение.
Вывод составителяВслух оценивайте решение формулой: «это O(n) по времени и O(n) по памяти». Интервьюер ждёт не точную цифру, а понимание, как решение поведёт себя на росте данных.
02

Структуры данных

list, dict, set, tuple — что и когда использовать.

Что спросят
  • Чем list отличается от set и dict?
  • Что общего у set и dict и почему они быстрые?
  • Когда список остаётся лучшим выбором?
Вопросы и ответы
list, set, dict — в чём разница?
list — упорядоченная последовательность с доступом по индексу, допускает дубли, поиск O(n). set — неупорядоченное множество уникальных значений, проверка вхождения O(1). dict — отображение ключ → значение, тоже O(1) в среднем по ключу.
Почему set и dict быстрые?
Оба реализованы на хеш-таблице. Ключ хешируется, и по хешу почти сразу находится нужная ячейка. Плата за это — требование хешируемости ключа (неизменяемый тип) и то, что set не сохраняет порядок вставки как гарантию.
Когда брать список?
Когда важны порядок, дубликаты или доступ по позиции. Например, поток событий, отсортированный результат, последовательность для двух указателей.
Пример
events = ["login", "login", "purchase"]

unique_events = set(events)          # {"login", "purchase"}
first_seen = {}                      # порядок вставки сохраняется
for e in events:
    if e not in first_seen:
        first_seen[e] = True

seq = sorted(unique_events)          # обратно в список
Частые ошибки
  • Пытаются положить в set или использовать как ключ dict изменяемый объект (например, список).
  • Ждут от set стабильного порядка — его там нет, если порядок важен, нужен список или dict.
  • Используют список там, где нужна частая проверка вхождения — получают O(n²).
Вывод составителяПростой тест на интервью: если нужен «вопрос: есть ли элемент / сколько раз» — это dict или set. Если «где он стоит и в каком порядке» — список.
03

Хеш-таблицы и частоты

Подсчёт частот словарём, дубли и две суммы.

Что спросят
  • Как посчитать частоту значений без pandas?
  • Как найти дубликаты в большом списке?
  • Как решить «две суммы» за один проход?
Вопросы и ответы
Как посчитать частоты?
Пройти по данным и инкрементировать счётчик в словаре. Это O(n) по времени и O(k) по памяти, где k — число уникальных ключей. На выходе — готовая основа для топ-K и фильтрации редких значений.
Как найти дубликаты?
Завести множество уже встреченных значений: если элемент уже там — это дубликат. Один проход, O(n). Альтернатива через частоты — собрать ключи со счётчиком больше единицы.
Как решить «две суммы» (two sum)?
За один проход храним в словаре уже встреченные значения и их позиции. Для текущего x проверяем, есть ли в словаре target - x. Это превращает наивный O(n²) в O(n).
Пример
from collections import Counter

countries = ["RU", "US", "RU", "DE", "US", "RU"]
freq = Counter(countries)          # {"RU": 3, "US": 2, "DE": 1}

def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:
            return (seen[target - x], i)
        seen[x] = i
    return None
Частые ошибки
  • Считают частоты вложенным циклом — O(n²) вместо одного прохода.
  • В two sum сначала строят словарь полностью, забывая, что нужно избегать пары «элемент сам с собой».
  • Хранят в словаре не тот тип ключа: список или другой изменяемый объект как ключ вызовет ошибку.
Вывод составителяCounter и обычный dict — рабочая лошадка DE-задач. Правило: если видите «сколько раз», «самый частый», «есть ли уже» — это словарь или множество, и решение почти всегда укладывается в один проход.
04

Два указателя и sliding window

Линейные проходы по отсортированным и непрерывным данным.

Что спросят
  • Когда применим метод двух указателей?
  • Что такое скользящее окно и как его двигать?
  • Как найти подряд идущий отрезок с нужным свойством?
Вопросы и ответы
Два указателя — это когда?
Когда данные отсортированы или важна пара «слева-справа». Двигая указатели навстречу или в одну сторону, за один проход проверяем все пары, не беря вложенный цикл. Классика — сумма пары в отсортированном массиве, слияние двух списков.
Как работает sliding window?
Окно — это непрерывный отрезок [left, right]. Правый указатель расширяет окно, левый поджимает его, когда условие нарушено. Такой проход линеен: каждый элемент входит и выходит из окна не более одного раза, итого O(n).
Пример на данных?
Поиск самого длинного отрезка дней без пропусков, максимальная сумма за окно из k подряд идущих событий, подсчёт подписок в скользящем 7-дневном периоде.
Пример
def max_sum_window(arr, k):
    window = sum(arr[:k])
    best = window
    for right in range(k, len(arr)):
        window += arr[right] - arr[right - k]
        best = max(best, window)
    return best

# для двух указателей список должен быть отсортирован
def pair_sum(sorted_nums, target):
    left, right = 0, len(sorted_nums) - 1
    while left < right:
        s = sorted_nums[left] + sorted_nums[right]
        if s == target:
            return (left, right)
        if s < target:
            left += 1
        else:
            right -= 1
    return None
Частые ошибки
  • Применяют два указателя к неотсортированным данным там, где нужна сортировка.
  • Пересчитывают сумму окна заново на каждом шаге — теряют линейность.
  • Двигают левый и правый указатели не по правилу условия, а «на глаз», и получают пропуски.
Вывод составителяСигнал к скользящему окну — слова «подряд», «непрерывный отрезок», «за период из k». Сигнал к двум указателям — «отсортированный» и «пара». Назовите это вслух до написания кода — интервьюер ждёт именно распознавания паттерна.
05

Сортировка, группировка и топ-K

O(n log n), группа по ключу и выбор самых больших.

Что спросят
  • Какова сложность сортировки и стабильна ли она?
  • Как сгруппировать элементы по ключу?
  • Как выбрать топ-K без полной сортировки?
Вопросы и ответы
Какая сложность у сортировки?
У sorted() и list.sort() — O(n log n). Сортировка Timsort стабильна: равные элементы сохраняют исходный порядок. Это позволяет сортировать по нескольким ключам последовательно — сначала по второстепенному, потом по главному.
Как сгруппировать элементы?
Через словарь списков: ключ → перечень элементов. Если данные предварительно отсортированы по ключу, пригодится itertools.groupby, но он группирует только подряд идущие одинаковые ключи.
Как достать топ-K?
Если K мало относительно n, полная сортировка избыточна — используют heapq.nlargest / nsmallest, работающие за O(n log K). Для K порядка n выгоднее обычная сортировка.
Пример
from collections import defaultdict
import heapq

logs = [("RU", 10), ("US", 7), ("RU", 4), ("DE", 9)]

by_country = defaultdict(int)
for country, cnt in logs:
    by_country[country] += cnt

top2 = heapq.nlargest(2, by_country.items(), key=lambda kv: kv[1])
# [("RU", 14), ("DE", 9)]
Частые ошибки
  • Сортируют весь массив, чтобы взять топ-3, — лишняя работа на больших данных.
  • Применяют groupby к несортированным данным и получают раздробленные группы.
  • Путают аргумент key сортировки с ключом словаря.
Вывод составителяТоп-K — это вопрос о том, нужна ли полная сортировка. Если да — O(n log n), если K мало — куча за O(n log K). Умение задать уточняющий вопрос про размер K отличает уверенного кандидата.
Итог

Общий вывод составителя

Алгоритмическая секция для DE проверяет не скорость написания кода, а выбор инструмента. Хеш-таблица (dict/set) превращает квадратичные решения в линейные, а два указателя и скользящее окно закрывают задачи на непрерывные отрезки.

Начинайте любой ответ с двух вопросов: какая структура данных нужна и какова сложность решения. Оценка «O(n) по времени, O(n) по памяти» вслух ценится выше, чем молчаливо верный код.

И держите в голове связь с работой DE: подсчёт частот — это groupby, дедупликация — это distinct через set, топ-K — это ORDER BY LIMIT. Алгоритмы здесь не абстракция, а та же обработка данных, только в коде.
