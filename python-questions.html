01

Типы и изменяемость

mutable/immutable, копирование и разница коллекций.

Что спросят
  • Что значит изменяемый и неизменяемый тип?
  • Чем отличается поверхностное копирование от глубокого?
  • list, tuple или set — что выбрать?
Вопросы и ответы
mutable и immutable — в чём разница?
Изменяемые объекты (list, dict, set) можно менять на месте — добавление и удаление не создаёт новый объект. Неизменяемые (int, str, tuple, frozenset) при «изменении» возвращают новый объект. Только неизменяемые могут быть ключами dict и элементами set.
copy и deepcopy?
copy.copy делает поверхностную копию: новый контейнер, но вложенные объекты остаются общими. copy.deepcopy рекурсивно копирует всё дерево — правки во вложенных структурах не затрагивают оригинал.
list, tuple, set — в чём разница?
list — изменяемый упорядоченный, допускает дубли. tuple — неизменяемый упорядоченный (можно использовать как ключ). set — неупорядоченное множество уникальных значений с быстрой проверкой вхождения.
Пример
import copy

a = [1, [2, 3]]
b = a.copy()          # shallow: вложенный список общий
c = copy.deepcopy(a)  # глубокая копия

b[1].append(99)       # изменит и a, и b
c[1].append(99)       # изменит только c
Частые ошибки
  • Считают, что = копирует объект — на деле это вторая ссылка на тот же объект.
  • Берут поверхностную копию и удивляются, что вложенные данные изменились вместе с оригиналом.
  • Используют изменяемый объект как значение по умолчанию в функции.
Вывод составителяКлючевая мысль: = не копирует, copy копирует неглубоко, deepcopy копирует полностью. Этого достаточно для девяти из десяти вопросов на эту тему.
02

Функции и область видимости

*args/**kwargs, локальные и глобальные имена.

Что спросят
  • Что делают *args и **kwargs?
  • Как работает область видимости и инструкция global?
  • Что не так с изменяемым значением по умолчанию?
Вопросы и ответы
*args и **kwargs — зачем?
*args собирает лишние позиционные аргументы в кортеж, **kwargs — именованные в словарь. Обратная операция — * и ** при вызове распаковывают коллекцию в аргументы.
Как работает область видимости?
Python ищет имя по правилу LEGB: локальная, объемлющая, глобальная, встроенная область. Присваивание внутри функции создаёт локальную переменную, если явно не объявить global (или nonlocal для вложенной функции).
Почему изменяемое значение по умолчанию — ловушка?
Значение по умолчанию вычисляется один раз при определении функции и живёт между вызовами. Если это список, он накапливает данные от всех вызовов. Обход — использовать None и создавать объект внутри.
Пример
def collect(item, acc=None):
    if acc is None:
        acc = []
    acc.append(item)
    return acc

# так делать нельзя: список общий для всех вызовов
def bad(item, acc=[]):
    acc.append(item)
    return acc
Частые ошибки
  • Пытаются изменить глобальную переменную без global и получают UnboundLocalError.
  • Используют список как аргумент по умолчанию и получают «протечку» данных между вызовами.
  • Путают *args в определении функции и * при вызове.
Вывод составителяПро *args/**kwargs отвечайте одной фразой: «собирают лишние аргументы, а при вызове распаковывают». Про умолчания — всегда добавляйте предупреждение про изменяемые объекты: это любимый вопрос интервьюеров.
03

Сравнения и коллекции

== и is, comprehensions и порядок словаря.

Что спросят
  • Чем == отличается от is?
  • Что такое списочные включения и когда их использовать?
  • Сохраняет ли словарь порядок?
Вопросы и ответы
== против is?
== сравнивает значения, is — идентичность объектов (один и тот же объект в памяти). Для чисел и строк малые значения могут кэшироваться, поэтому is иногда «случайно» работает, но полагаться на это нельзя. Для сравнения с None используют именно is.
Что такое comprehensions?
Компактный синтаксис построения коллекции с фильтром и преобразованием: [x*2 for x in data if x > 0]. Работает для списков, словарей и множеств. Читается лучше цикла и обычно быстрее, но не стоит вкладывать слишком много логики в одно выражение.
Сохраняет ли dict порядок?
Да, начиная с Python 3.7 порядок вставки гарантирован официально. Но это не сортировка: чтобы упорядочить по ключу или значению, словарь сортируют явно через sorted(d.items()).
Пример
a = [1, 2, 3]
b = [1, 2, 3]

print(a == b)     # True — одинаковые значения
print(a is b)     # False — разные объекты

squares = {x: x ** 2 for x in range(5)}
ordered = dict(sorted(squares.items()))
Частые ошибки
  • Сравнивают значения через is и получают неверный результат на больших числах и строках.
  • Проверяют x == None вместо x is None.
  • Пишут comprehension с побочными эффектами внутри — теряют читаемость.
Вывод составителяОдна строка для интервью: «== про значение, is про тот же объект». И не забывайте: порядок dict — гарантия языка с 3.7, но не сортировка.
04

Исключения и окружение

try/except, GIL и виртуальные окружения.

Что спросят
  • Как правильно обрабатывать исключения?
  • Что такое GIL и как он влияет на многопоточность?
  • Зачем нужны virtualenv и venv?
Вопросы и ответы
Как обрабатывать исключения?
Через try/except с конкретным типом исключения, а не «голым» except. Блок finally выполняется всегда — там освобождают ресурсы. Ловить всё подряд (except Exception) скрывает баги: лучше перечислить ожидаемые типы.
Что такое GIL?
Global Interpreter Lock — блокировка, из-за которой в CPython одновременно исполняется только один поток байт-кода. Поэтому потоки не ускоряют CPU-задачи; зато они полезны для I/O (сеть, диск, БД). Для параллельных вычислений используют процессы или библиотеки, отпускающие GIL.
Зачем virtualenv и venv?
Изолируют зависимости проекта: свой набор пакетов и версий, чтобы проекты не конфликтовали. venv — стандартный модуль Python, virtualenv — более старый сторонний инструмент с расширенными возможностями.
Пример
try:
    value = int(raw)
except ValueError:
    value = 0
except (TypeError, KeyError) as e:
    log.error("bad input: %s", e)
finally:
    close_connection()
Частые ошибки
  • Пишут except: без типа и глушат все ошибки, включая опечатки в коде.
  • Ждут ускорения CPU-задач от потоков и упираются в GIL.
  • Ставят пакеты глобально, а потом не могут воспроизвести окружение.
Вывод составителяПро GIL отвечайте через различие нагрузок: «для I/O — потоки, для CPU — процессы». Это показывает, что вы понимаете не только определение, но и когда какой подход применять.

Даты и практика

datetime, часовые пояса и типичные вопросы о коде.

Что спросят
  • Как работать с датами в Python?
  • Почему важны часовые пояса?
  • Как сравнить две даты или найти разницу?
Вопросы и ответы
Как работать с датами?
Стандартный модуль datetime: классы date, datetime, timedelta. Строки парсят через datetime.strptime или dateutil.parser, а обратно форматируют strftime. Вычитание двух datetime даёт timedelta.
Почему важны часовые пояса?
Наивные (naive) даты без зоны дают неверные сравнения между регионами. Для корректности используют aware-даты с tzinfo (модуль zoneinfo), хранят время в UTC, а в локальную зону переводят только при выводе.
Как найти разницу дат?
Вычесть одну дату из другой — получите timedelta с днями, секундами и микросекундами. Для календарных месяцев/лет нужны дополнительные библиотеки, так как длина месяца переменная.
Пример
from datetime import datetime, timedelta, timezone

now = datetime.now(timezone.utc)
start = datetime(2026, 1, 1, tzinfo=timezone.utc)

delta = now - start
print(delta.days)

text = start.strftime("%Y-%m-%dT%H:%M:%S")
Частые ошибки
  • Сравнивают naive-дату с aware-датой — получают TypeError.
  • Хранят локальное время без зоны и теряют один-два часа при переходе на летнее время.
  • Считают, что в месяце всегда 30 дней, при вычислении интервалов.
Вывод составителяПравило, которое стоит назвать на интервью: «храним и сравниваем в UTC, в локальную зону переводим при отображении». Оно снимает почти все вопросы про даты и часовые пояса.
